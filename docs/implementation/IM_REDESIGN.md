# 微信式聊天与15位人物：实施记录

2026-10-30。依据用户确认的方案完成；该界面替代纸感阅读式聊天，原有长期记忆、来源隔离和模拟授权规则继续适用。

## 产品与视觉

桌面64px功能栏＋280px人物/最近会话列表＋全高聊天区。人物资料为按需抽屉；手机采用列表/单聊两个视图。固定标题、独立滚动消息、底部输入框、左右气泡与本地插画头像。全站无衬线字体，消息16px，使用已确认的蓝白色板。六个原页面与深链接仍可访问。

人物按五领域可搜索筛选，固定前三芒格/巴菲特/张雪峰。头像均由内置image_gen按单人独立生成，15张；仅等比缩为256px PNG，总1,951,469字节。选定原图保留于artifacts/portrait-originals，实际交付位于frontend/public/portraits，精确提示词与生成文件对应见AVATAR_ASSETS.json。庄子是历史想象插画，其他头像也不是本人照片。

人物资料按固定上游版本保存原文、完整MIT许可和转换指纹。运行时只使用WOT整理后的静态角色数据，资料正文不出现在列表/详情摘要中。来源核查范围与局限见PERSONA_CATALOG.md，未用上游自评分数证明人格拟真。

## 状态、接口与兼容

- 人物摘要增加slug、领域、标签、avatar_url、三个starter_prompts、来源与版本；GET /api/v1/skills/{id}返回安全资料摘要。内置目录按稳定ID逐项补入，不覆盖已有自定义或已编辑人物。
- 会话补skill_id、updated_at、last_message_at、last_message_preview，按真实活动排序。预览与话题按钮不创建空记录，首次发送才创建；同人物的不同话题保持独立。
- 消息补sequence、client_request_id、deleted、reply_state与可用时的retry_payload。新消息保存最初domain/remember，发送失败后USER仍可见，刷新也能按原key和原body重试。v1缺失参数的旧消息不猜测可重试payload。
- 草稿、消息与滚动位置按会话存于应用内存，不写浏览器永久存储。每条记忆批准发送后复位；读取历史不会因全局状态更新强制滚底。切换人物后在途回复仍归原会话。
- v2迁移先备份到wot.pre-v2.<时间戳>.db，原ID和证据关系保留。删除同步清理消息、标题、预览、回执、前端缓存及依赖快照/模拟；升级也修复旧版本已删来源留下的自动标题。

## 实际发现与修复

第一次浏览器联调暴露了共享SQLite连接读取未与写事务串行的问题：首次创建会话后，前端并发历史读取与发送出现404/数据库接口错误。修复为AppStore.fetchone/fetchall在同一短锁中执行并消费游标，所有应用读入口使用该边界；生成期间的暂停仍只持短事务锁。第二次独立空库完整验收通过。失败证据保留于frontend/artifacts/im-e2e/attempts/001-read-race。

同时补齐deleted标志在准入入口的拒绝、已删除标题历史修复、旧请求参数不可反推的迁移边界、角色上下文静态清理与原文导出的区分。没有通过跳过用例或删断言消除失败。
