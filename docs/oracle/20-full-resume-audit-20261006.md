## 独立审计

新增 `audit_tools/audit_adjudicated_result.py`，在全量结束后独立检查：

- 必须拥有全部 500 题，不允许只报已成功或已判分子集的准确率。
- 全量前后形成记录、检索结果和实际可见证据相同；每题符合 6,000 启发式证据预算。
- 每个阅读阶段和最终回答的引用必须出现在其指定的可见条目中，且来源一致。
- 提交逐行与保存的回答一致；失败输出的统一拒答回退不能获奖。
- 判分对应准确的数据版本和答案摘要；基线与候选 judge 规格一致。
- 冻结源码、依赖以及独立恢复工具在执行期间保持一致。

发现原 runner 在续跑后只将本次新失败写入 `failures.json`，会漏掉检查点中的失败，甚至可能错误标为 `COMPLETED`。本次实际存在 7 条无效输出，而旧文件只列出 6 条。完整准确率按全部逐题 trace 计错，审计另写完整 `audited-failures-20261006.json`，保留原冻结产物供核对。

10 月 7 日已修复：最终失败清单从全部已保存结果重建，包括检查点。两个合成回归分别复现了“全部从检查点恢复却误报成功”和“新旧失败混合时漏报历史失败”，修复后均通过。修复在冻结版全量运行和独立审计完成之后进行；冻结版原始 `runner.py` 与 `adjudicated_reader.py` 保存在实验目录 `frozen-source/`，不改写此前判分。

## 证据端的进一步发现

对既有 366/500 基线的 132 道可答错题进行离线分层：32 题存在至少一个未形成的标注来源，4 题存在未检出的标注来源，96 题全部标注来源已经可见。最后一类不能直接归为模型推理错误：同一条消息只留下泛泛短句时，来源覆盖仍会显示成功，答案所需原句却可能丢失。

开发样例中已经确认的内容缺口包括购买专辑的经历、模型套件名称、社交挑战名称及长篇案例材料中的年份。另一些错误的证据确实完整，例如贷款额度的先后更新、相对日期，以及跨来源的家庭事件先后关系。后续应分别验证事实保留、来源代表片段选择和有据推导，不能把它们统一当作算术问题。

对全部 500 题的 7,809 条可见证据进行来源角色审计：4,726 条显示 `unknown`，其中 4,555 条可从实际来源确定为用户，171 条为助手，后者涉及 103 题。仅凭语句的第一人称不能区分用户经历与助手建议。已有可选来源坐标方案曾在另一组配置上未通过筛选，因此本轮不直接切换配置；角色审计不代表已经证明提分。

这些诊断只在评估侧读取标注；没有将参考答案、题型或题目 ID 加入 reader 路由或证据。

## 格式容错的边界与免费验证

`AdjudicatedReader(..., recover_invalid_secondary=True)` 为可选策略，拥有独立版本及配置指纹。仅在第二轮为 `INVALID` 且首轮为已校验的 `ANSWER` 或 `ABSTAIN` 时保留首轮结果。真正拒答仍进入原有分歧处理，传输失败与超时仍报失败，两轮均无效仍报失败；不按题型、题目 ID 或答案对错选择路径。原默认行为保持不变。

`audit_tools/replay_format_recovery.py` 对全部 500 题调用同一运行时策略，并使用已保存的真实阶段结果。493 题的结果除策略版本标记外逐字段核验不变；另外 7 题采用首轮有效回答。路由完成后才加载评估结果，按完全一致的答案及 reader 状态复用已有 judge 判分；所有引用、证据与提交再次验证。产物明确标记为 `saved_stage_replay`，不将继承的 token 与耗时称为新增调用。

7 个恢复回答中 2 个正确、5 个仍然错误，因此只净增 2 题。它解决的是有效首轮答案被格式错误丢弃的问题，没有证明原来的错误内容变正确，也不保证未来所有请求都能避免无效输出。相对 395 版本是 2 题改善、0 题退步、新增 API 调用 **0**。

最新回放剩余 **59 次误拒、44 次错误作答**，其中 2 次错误作答来自不可答题。后续重点仍为必要事实保留、时间推导和实体/范围对齐；不把移除格式失败当作已解决这 103 道题。
