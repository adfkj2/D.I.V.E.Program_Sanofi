# 个人项目助手开发验收

这里保存 R51 在运行前冻结的合成场景定义。使用真实供应商、生产 Agent 链路和独立临时数据库；不读取用户项目，也不使用 Oracle 题集。

- `acceptance-v1.json`：10 项基线发现任务，以及首轮修复后使用的 6 项复核任务。
- `acceptance-v2.json`：首轮复核发现改写标题导致重复待办后，重新冻结的 6 项最终复核任务。

每项按定义建立独立项目、待办、交接或记忆，发送 `prompt`，先检查提案确认前项目状态不变，再按预期动作审阅和确认，检查持久化状态、替换关系及另一个项目的隔离。只读、取消和歧义场景不得写入。最后人工检查回复是否准确回应请求、区分提议与事实，不能只以结构检查或出现确认按钮判定通过。

场景和判读均由开发者完成，不是独立盲测或真实用户研究。某组结果一旦用于诊断，后续只作为开发回归；不同组的通过率不能直接解释为同一测试集上的准确率提升。最终 6/6 只支持所测范围内的个人试用门槛。

完整原始运行及计费脚本保存在本地忽略目录 `eval/reports/agent-acceptance-20261016*/`。当前脚本依赖本地历史计费辅助文件，**本目录不提供可独立执行的联网 runner**；可根据夹具通过应用逐项手工复核。重新运行会产生模型费用，不应在 CI 自动调用。无模型工程回归仍由 `python tools/check_quality.py` 执行。
