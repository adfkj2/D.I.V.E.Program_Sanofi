## 最终实现

- 明确来源分工：当前目标、待办、完成状态、最近交接直接来自项目上下文；已保存的决定、指标、约束和结果通过记忆检索查证。历史对话不充当事实依据，不因上一轮谈过某个指标就在只问进度时继续查询它。
- 回答和提案摘要默认用任务名称、记忆主题及日常状态词，按用户的问题讲决定、进展和下一步。内部编号、版本等保留在工具参数及引用字段，来源按钮仍然可用。用户明确排查技术问题时允许按需解释字段，未采用可能误删业务内容的字符串过滤。
- 精简上下文：待办保留操作所需的编号、名称、状态和版本，交接保留正文、下一步及时间。增加全项目任务计数和明细截断标记，避免把最多50条明细当成全部；交接仍仅包含最近3条。
- 没有硬性禁用二次检索或缩小工具预算：缺少证据时仍可补查、读取原文。确认、原子写入、引用检查及项目隔离边界不变。

变更只涉及 Agent 提示规则与应用上下文适配；不把产品话术引入 benchmark，模型接口、记忆核心和网页渲染逻辑保持原有分层。
