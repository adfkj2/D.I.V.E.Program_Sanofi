# 从 62.2% 到 90%：差距、改造与验收记录

开始日期：2026-09-28；最近更新：2026-09-29。当前已核验的完整成绩为 **366/500（73.2%，DeepSeek Flash 非官方自评）**，上一版为 311/500。目标是在完整 500 题上达到至少 450 题正确，而不是在筛选样本上达到 90%。还差 84 道净增正确，目标尚未完成。下文按实验发生顺序保留记录。

## 与高分方案相比，差在哪里

2026-09-28 核对了 [Mem0 的公开评测仓库](https://github.com/mem0ai/memory-benchmarks)。其托管方案报告 LongMemEval top-50 为 94.8%，top-200 为 94.4%；开源方案中，GPT-5 抽取＋GPT-5 作答和判分、Qwen 600M embedding＋Qdrant 的结果为 91.0%。这些是项目方公开报告，不是我独立复现的结果。

它们与本项目的 Oracle 输入、Flash 作答/判分、1,500 证据预算并非同一条件。不能据此宣称“换成 Mem0 就能提高 29 个百分点”，也不能认为分差都来自存储引擎。

| 环节 | 本项目的已知不足 | 为什么会妨碍高分 | 本阶段行动 |
|---|---|---|---|
| 写入 | 依赖规则和单句抽取，具体信息分散在邻句时容易丢失 | 有来源 ID，但所需数字或指代没有保留下来，之后再检索也找不回 | 有筛选的原文叙事窗口；先不使用付费抽取模型 |
| 检索 | top-10 容易被同一个来源的多条原子记忆占据 | 聚合、清单、跨会话题需要多个不同事件，不只是最相似的几句话 | 从更大候选池优先选不同来源，再比较扩大 top-k/预算 |
| 文档 | 助手原文受到独立文档数量与截取限制 | 即便总体预算增加，某些局部上限仍不会放宽 | 先记录限制，后续单独测；不同时改变所有变量 |
| 阅读 | 100 道可答题误拒；原文齐全也可能算错或混淆事件时间 | 检索覆盖不等于最后正确率 | 简化阅读接口，保留实体和缺失前提要求，不以放松拒答换分 |
| 引用协议 | 模型必须复制长 memory/source ID，9 道输出无效 | 正确内容也可能因机械格式丢分 | 让模型输出证据编号与原文引文，由程序映射真实来源；错误仍计错 |
| 评测 | Flash 同时作答和判分，正式 judge 未确认，公开数据已用于开发 | 本地 90% 不能自动等同比赛或未知数据 90% | 固定口径、保留逐题答案与失败，后续获得指定 judge 后再核验 |

距离至少 450/500 还差 **139 道净增正确**。当前 189 道错误的首个可观测缺口包括：写入不足 36、检索不足 53、来源回合均已装包但仍错 85、无效输出 9、不可答错误作答 6。“来源回合已装包”并不保证关键句齐全，因此不能将那 85 道全部归为模型推理能力不足。

## 本阶段已经实现什么

### 有筛选的叙事窗口

`NarrativeRetentionPolicy` 只处理用户来源，整回合先执行敏感检测。原有写入门已接受的个人材料，或具体经历规则接受的句子，可以成为锚点；围绕锚点保留有限的相邻原句。窗口最多 1,800 字符、每回合最多 4 条，超过 8,000 字符的回合不经此策略处理。相邻窗口在限额内合并，保留精确字符区间。

这是查询无关的写入策略，不读取问题、答案或标注来源，不临时回查未进入记忆的原始历史。结果标为观察而非核实事实，邻句可能包含问题或假设，不能把整个窗口的每一句自动提升为用户事实。仍使用原来的隔离、用户关闭记忆、时间可见性和遗忘机制。

### 来源多样化

可选地从 top-k 三倍的候选池中，优先选择尚未出现过的来源事件，再补同源条目。它解决的是多个条目反复占用同一来源名额的问题，不是一个新的语义重排模型，也不能判断所有事件是否齐全。没有来源的条目按各自记忆 ID 区分，不将它们误当成同一个来源。

### 编号引用阅读器

`IndexedEvidenceReader` 让模型输出 `index + quote`，程序将 index 映射到已有记忆 ID 和来源链。引文必须仍是可见证据的连续原文，索引必须是范围内的整数；不存在的编号、伪造引文、拒答中混入答案均不接受。最多一次格式/引用修复，不反复追问一个有效拒答。

编号映射是机械操作，不是替模型补证据。阅读器继续检查预算内的原文块，拒绝与条目内容不一致的上下文。没有参考答案进入提示。

### 已实施、尚待端到端验证的修复

1. **混合句中的事实锚点。** 可选 `narrative_clause_anchors` 将普通因果/转折/并列句划分为子句，只有同时具备个人主体、事件及具体细节的独立陈述可以成为锚点。例如“我打算补买，因为我的背包三天前丢了”能保留丢失经历；“如果我昨天买了四张票”不能。整个条件/虚构范围和问句不通过此新规则；存储仍是带精确原文区间的观察记录，而非将未来计划变成稳定事实。规则仍有语言覆盖局限，不宣称修复了全部家庭关系、习惯或问句中的隐含事实。
2. **命中片段展开。** 从已经写入的原始文档中展开命中范围，优先恢复所在行/清单项的开头，保持一个连续的原文片段和字符上限。原始事件不被临时检索，来源不会被换成模型摘要。候选实验将独立文档限额从 2/600 调整为 4/2,400，并采用 2,400 字符片段上限；全局证据预算仍为 6,000。非文档先装包，文档不能挤掉已经入包的事实。增加局部配额属于实验变量，不是免费获得更多信息。
3. **修复去重索引被覆盖。** 原实现使用同一个变量保存“规范值到位置的字典”和“合并来源坐标列表”，出现重复条目后，下一个条目可能触发类型错误。新增三条重复记忆及合并后继续装包的合成用例已复现并修复。不能将这个工程缺陷自动解释成此前 500 题的失分来源，旧全量并未记录这类运行失败。

改动后回归为 **584 passed，9 skipped**，通用默认不启用新策略。`oracle-context-repair-20260929` 对照旧版、仅混合句、仅文档展开、两者组合；采用同一批思考实验筛选题以复用基线，不把它说成新的盲测。先要求每一题型来源覆盖不下降，再允许有覆盖或可见文本增加的候选进入付费筛选。文本更长只是实验准入条件，不是准确率；付费推广仍要求可答至少净增 3/50、不可答不下降。
