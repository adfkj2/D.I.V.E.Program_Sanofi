## 独立审查发现的保护缺口

审查先复现再修正了以下问题，失败日志完整保留：

1. 初版分析重新编号仅按记忆ID、来源子集与正文包含匹配，可能跨项目、版本、角色或时钟沿用。现仅允许当前窗口包含旧正文，并在临时恢复旧正文后完整语义快照一致；实际复核传入草稿所引快照，按引用顺序验证。
2. 初版空来源support缺陷可盲改数值。现仅允许其解释最终必要拒答，ANSWER修订必须提供当前来源；仍需真实语义评估判断缺陷是否成立。
3. 关闭记忆时跳过的事件重新开启后可在重建时复活。现持久记录事件投影禁用，队列、重启与重建共同遵守；原Event仍作审计保留。
4. 同源全文观察可能复活已忘事实；原候选索引变化又可能使已忘事实换ID重现，或使独立未忘事实撞上旧墓碑。现同源观察被持久阻断，同源同文投影另存内容指纹；索引冲突仅在有新来源保护标记时为独立未忘内容生成稳定替代身份。旧无完整保护证据的墓碑保持保守。此机制针对同源相同原文，不宣称识别任意改写的语义等价。
5. 用户角色别名与来源注释不一致。现统一已有用户来源集合并做首尾空白/大小写归一，明确不记忆要求在普通抽取前生效。
6. 明确不记忆/敏感排除只在当前抽取策略生效，更换策略后可重建成FACT。新增显式exclude_from_replay结果并持久记录事件投影排除，普通低效用跳过仍可重处理；跨重启、换抽取器反例已通过。

这些保护跨SQLite与PostgreSQL使用公开存储接口，原Event审计正文没有被单条记忆忘却操作擦除。事件级删除保留既有合同；不以整源删除全部独立事实代替正确的投影保护。
