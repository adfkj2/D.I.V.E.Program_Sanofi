# 人物质量评估与严格个人校验

`backend/wot/assessments.py` 仅在用户开始或继续评估后请求模型。连接测试、普通聊天与评估使用不同调用用途记录。没有真实连接时不能启动评估；任何一轮出现 `MOCK` 结果都不会获得正式许可。

## 人物资料质量评估

资料是数据，不执行其中的脚本、工具、联网或权限声明。模型给出完整性、来源说明、思维与表达规则、一致性、权限与诚实边界五项等权分数、问题片段和修改建议。综合分至少80、每项至少70、关键权限和身份诚实检查全部通过才通过。服务器额外检查来源、许可声明和明确的提权、泄密、执行指令。

报告绑定草稿 ID、语义内容哈希和版本。添加时重新比较当前草稿，编辑正文或元资料后旧报告不能继续准入。头像不参与哈希。内置角色使用人工整理来源，不伪造此报告。

## 严格个人校验 v1

1. 开始时冻结获授权的真实资料、画像版本、资料截止时间、连接和模型配置哈希。
2. 通过四次独立生成准备40道新的情境题，覆盖十类领域。准备请求不包含用户画像或答案；答案不由模型生成。检查完整结构、三个不同且合理的选项、重复及与历史暴露题目的近似程度。每轮题目保存在评估私有库，不重复使用固定题集。
3. 用户逐题提交真实选择和理由，提交后冻结。部分作答可保留后继续；不能把答案通过普通记忆接口重新送入本轮画像。
4. 对同一题运行无画像、静态简介、普通摘要和用户 Skill 四个条件。预测按五题一批请求，统一底模、截止时间、上下文字符上限、温度和输出预算。预测请求完全不含保留答案，四组顺序按任务标识轮换。
5. 每题独立随机打乱四个候选，只给匿名候选名称，由辅助模型比照本人参考回答。决策选择由服务器直接比较；其余四维由匿名辅助判分。依据 ID 必须来自该条件获授权的来源，不能编造引用。辅助判分还检查参考回答是否实质回应本题，空泛或无关参考不算有效题。
6. 本人核验所有争议题和至少12道随机抽样题。核验接口只接受接受/不接受和说明，不能提交分数或通过标记。未接受的判分阻止本轮颁发许可。
7. 服务器以未四舍五入数值计算决策30%、理由价值25%、情境一致性20%、风格15%、依据边界10%。40题有效且完整、综合至少85、每维至少75、关键检查全过、Skill严格优于三个基线中最高分，才形成可确认的通过报告。
8. 本人确认报告后才颁发许可。标签为“本轮严格个人校验通过”，注明样本、覆盖情境、模型、截止时间与版本；不将它描述为科学的人格克隆概率。

每轮服务器预算上限250,000个实际总 token；中断、配额、格式或预算错误保留为“评估未完成”，不能被写成人格不合格。模型可能生成结构不完整、无效或近似题目，此时停止并允许用户手动继续；不会悄悄重试计费。

## 私有数据与失效

`assessment-private.db` 单独保存冻结上下文、保留答案、预测、随机匿名映射和逐题判分，不向普通状态、记忆构建、检索或模拟提供适配器。本人专用的评估详情接口在核验阶段展示参考答案和匿名候选。普通状态只含任务进度和不引用保留答案的汇总报告。辅助模型的自由文本判分可引用参考答案，因此也只留在私有库。

许可绑定 `profile_version_id`、`strict-personal-v1` 和模型配置哈希。昵称、头像和 Key 轮换不在哈希中。新增真实资料积累为下一版，不替换已校验版本。删除或撤销依赖来源会同步取消在途结果、清空受影响的冻结画像和预测、使报告和许可失效；私有保留答案仍独立存放。运行中任务在服务重启后暂停，手动继续才请求模型。

同步失效只获取应用数据库锁，不反向获取评估锁。所有在途结果的检查与私有提交共享应用数据库事务边界，避免删除后晚到结果恢复上下文。

## 验证

`tests/test_assessments.py` 使用独立临时数据库与无网络供应商，覆盖40题、答案冻结与隔离、四条件相同预算、匿名判分、本人确认、假分数拒绝、模拟结果不得解锁、模型绑定、删除传播、版本准入、低分建议、网络错误和在途删除。

这些隔离测试只验证程序规则。测试成绩不写入正式数据，也不颁发可用于产品的正式许可。
