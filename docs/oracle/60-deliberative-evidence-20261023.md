## 与公开前沿如何比较

## 新架构与解耦

1. **证据工作区**：只接纳来源接口已允许的内容，累计不可变快照。按批次和来源轮询装包，受同一近似token预算限制。相同来源产生的不同记忆ID共用公平位置，所有未展示片段留审计记录。
2. **搜证计划**：模型摘录最多16条原句，再提出至多2次搜索和2次读取。计划、答案使用不同格式，避免一个输出同时承担工具动作和最终回答。
3. **答案合成**：用累积证据回答，区分实体、事件时间与发言时间、计划与已发生、重复总数与新增量。拒答必须说明必要缺失前提。
4. **最终复核**：实际证据和明确标为不可信的草稿一起交给模型重新判断。草稿不是新的证据。每条最终引用严格绑定当前片段索引。

总计3个必需模型阶段，共享最多1次格式修复，最多4次调用。各阶段保留上下文、输出、哈希和装包审计；传输失败及用量未知保留失败，不隐式重试。

代码分为[协议与提示](../../src/dive_memory/reading/deliberation.py)、[工作区](../../src/dive_memory/reading/workspace.py)、[阶段编排](../../src/dive_memory/reading/deliberative.py)，经[应用工厂](../../src/dive_memory/application/readers.py)注入模型与来源接口。生产reader不读取评测答案、历史判分或实验目录。原adaptive和Oracle兼容入口保持。

新的原句锚定绑定文档快照、位置及原可见上下文。已复现并修复“同记忆ID不同片段掩盖错误引用索引”“相同短句定位到另一日期标题”和“派生记忆伪装为独立来源”三个边界。

## 已知局限

- pin优先保留已选证据，可能占满预算并挤出新反证。审计会显示省略；不保证所有来源始终可见。
- 同一模型的复核不是独立评审，可能重复或放大草稿错误。需要记录改善与退步，不能只报改对的题。
- 两个搜索在看到搜索结果前规划，多跳追证仍有上限。新增原文读取不能绕过时间、命名空间与遗忘边界。
- 新策略暂不调用calculate，算术和日期交给模型；可能减少格式错误，也可能失去旧工具成功路径的收益。
- 3个必需阶段增加延迟和token。既有写入与检索链保持，记忆形成遗漏不会自动解决。
