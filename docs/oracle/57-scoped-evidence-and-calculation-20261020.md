## 实现与边界

1. **事实作用域。** `ContextualFactRetention(scoped_assertions=True)`区分明确假设和非条件性的间接请求，例如“wondering if you can…”。“举一个例子”本身不再让同句中的已陈述事实消失；带引号的名称和有具体细节的所属人物过去经历可以作为观察锚点。明确的虚构、翻译、改写、纯计划和未知条件仍不能成为新锚点。保留原句、模态、位置和来源，写入OBSERVATION，不自动提升为确定事实；继承的其他写入策略保持原行为。
2. **长文分段查证。** 显式`verified`阅读策略从已入库记忆中最多选择两个不重叠的相关片段，两段共用原2400字符上限。目录携带原文位置，仍可读取指定位置。每次证据总预算和命名空间/时间/删除约束不变；不读取未获准的原始对话档案。
3. **有据计算。** 通用计算器移入`reading/calculation.py`，旧Oracle入口保留兼容导出。模型在原4次调用限额内选择计算操作及原句中的数值、标签；工具核验完整数值、精确引用、重复来源、近似值和日期边界。新策略另拒绝跨来源的同名范围相加，防止把旧总数与新总数累加。计算结果只作为工具观察返回，最终仍须引用原文；后续查证使旧计算失效。

计算器证明的是数值出处和运算，不证明语义范围或证据齐全。不同标签可能仍指同一对象，同一标签也可能对应不同事件；模型必须判断，严格工具可能拒绝本来可以合理计算的问题。不能把“运算正确”当作“问题答对”。每轮仍至多4次模型请求，最后一轮不能请求工具，错误不会被当成零或正确拒答。

默认`r40`和旧`adaptive`策略不变。候选必须显式启用：

```text
python -m dive_memory.application.oracle_run --dataset path/to/longmemeval_oracle.json --output path/to/new-run --reader-strategy verified --fact-policy scoped --reasoning-effort high
```

上述命令仅输出计划；执行还需原有`--execute`、凭据与请求/token/费用上限。产品的可选阅读入口可使用`DIVE_READER_STRATEGY=verified`，Agent日常提案确认与手工记录不自动改用实验写入规则。
