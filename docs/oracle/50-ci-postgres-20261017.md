本机未配置 PostgreSQL DSN，八项集成测试一直明确跳过；此前只核对本地质量结果和推送成功，未在交付前跟踪远程失败。这是交付核验遗漏。本地 SQLite 产品测试通过，不等于 PostgreSQL 服务契约已经通过；此问题也不是 API Key、模型或本次 Agent 行为改动造成。

## 修复

- 将已有的隔离数据库准备提取为共享 pytest fixture，每个存储/队列用例创建自己的 schema，先执行全部迁移，再把带 search_path 的 DSN 显式传给所有连接，包括并发线程、核验及清理连接。
- 用例结束只清理该 fixture 创建的 schema；保留原有数据、并发、回滚、隔离、时间状态和向量检索断言。不修改生产数据库初始化策略或历史 SQL 迁移。
- CI 额外检查 PostgreSQL 测试报告，要求确实有用例执行，且失败、错误、跳过均为零，避免缺依赖变成假绿。
- 仓库工作说明新增推送后逐项等待远程检查、失败读日志、跳过不作通过的交付要求。
