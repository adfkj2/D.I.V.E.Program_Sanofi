## 修复与边界

可选`verified`策略升级为`scoped-evidence-reader-v2`，旧`adaptive-evidence-reader-v3`与默认配置保持原行为。独立的[工具协议模块](../../src/dive_memory/reading/tool_protocol.py)负责请求字段校验，不依赖存储、模型提供商或评测器；[阅读循环](../../src/dive_memory/reading/adaptive.py)负责调用预算和错误分类。

| 情形 | 修复后的行为 |
| --- | --- |
| 工具缺少必填字段 | 反馈具体缺项，允许模型在原有最多4次调用内修正；不补默认参数、不执行不完整请求 |
| 重复工具请求 | 不再执行，反馈后允许换查询或作最终回答；搜索首尾空格归一化后去重 |
| 新计算失败 | 在校验新请求前清除旧成功计算，避免旧结果与新错误混用 |
| 存储来源抛异常 | 明确`EVIDENCE_SOURCE_FAILURE`，一次终止；不误作可修复模型参数、不隐式重试 |
| 超额字段、混入答案、未知来源或非法值 | 仍拒绝；先查额外字段再报缺项，不能借缺字段放过混合答案 |
| 最后一次调用仍请求工具 | 明确INVALID，不增加调用、不制造拒答来掩盖失败 |

计算提示明确`unit`字段必须存在，标签必须是原句的精确子串；日期、数值、近似表达、重复范围和原句引用校验均未放松。算术成功也不代表语义范围正确。

R62的16个无效输出中，9个缺unit和5个重复动作发生时仍有调用余量，属于本次机制覆盖的失败类型；另外2个在最终轮出现JSON或引用错误。本轮没有让真实模型重答这14题，不能把它们计成已修正答案；生成中断及判分未知也仍保留。
