## 修复

- 将已有的隔离数据库准备提取为共享 pytest fixture，每个存储/队列用例创建自己的 schema，先执行全部迁移，再把带 search_path 的 DSN 显式传给所有连接，包括并发线程、核验及清理连接。
- 用例结束只清理该 fixture 创建的 schema；保留原有数据、并发、回滚、隔离、时间状态和向量检索断言。不修改生产数据库初始化策略或历史 SQL 迁移。
- CI 额外检查 PostgreSQL 测试报告，要求确实有用例执行，且失败、错误、跳过均为零，避免缺依赖变成假绿。
- 仓库工作说明新增推送后逐项等待远程检查、失败读日志、跳过不作通过的交付要求。

## 首次复验暴露的运行缺陷

修复提交 `e72d92c` 的[真实远程复验](https://github.com/adfkj2/D.I.V.E.Program_Sanofi/actions/runs/38994465278)为 PostgreSQL **6 通过、2 失败**。测试已能进入真实业务路径，进一步暴露：

1. 硬删除调用 `hot_memory.redact`，其内部直接访问 SQLite 的 `store.db`；PostgresStore 没有该接口。改为存储方法 `redact_profile_history`：SQLite 保留原有提案/历史内容清理，PostgreSQL 清理其实际存在的当前画像缓存，随后由服务按剩余记忆重建。PostgreSQL 尚不支持 SQLite 的画像修订功能，不虚构对应表。
2. 两个连接同时发现 embedding_state 为空，随后都尝试插入单例记录。数据库日志证实 `embedding_state_pkey` 冲突，另一线程最终报 BrokenBarrierError。改为原子插入、冲突时保留原记录，再读取并核对有效代际，仍拒绝不同代际混用。

本地派生画像和迁移定向检查12项通过；完整质量门禁与第二次远程验证另行记录。此处修复实际存储行为，保留首次失败，不以放宽断言或增加等待时间解决。
