# 固定输入的机制对照

`stories-v1.jsonl`从原有R42的30个开发故事冻结而来：120项任务、6类重复模板。它不是新的独立测试集，也不度量自然语言抽取或LLM问答。复用同一批任务可以把新增“关闭遗忘”与重启持久化检查放到可比较的条件下；不把这次重跑算成新增准确率。

安装项目后运行（不依赖历史报告、eval中的Python辅助脚本或联网服务）：

```text
python -m dive_memory.mechanism_validation --fixtures eval/mechanisms/stories-v1.jsonl --output eval/reports/my-mechanism-run
```

输出目录必须不存在。所有臂接收同一事件集合与任务、全部输入可见，不设token预算。读取方式固定为确定性的已确认字段查询，参考答案仅供结果比较，不进入写入或查询参数。

| 实验臂 | 唯一改变或基线定义 |
| --- | --- |
| memory | 完整结构化项目记忆，写入后关闭数据库，查询前重新打开 |
| without_updates | 写入时不传显式替换关系；其余同memory |
| without_source_gate | 把非用户来源也当作用户记录接纳；只消融来源门，不代表所有选择性写入 |
| without_forgetting | 不执行删除操作；其余同memory |
| event_scan | 扫描全部结构化事件，执行相同来源、更新、历史时间与删除语义，作为强简单基线 |
| rolling_summary | 每个字段保留最新确认值；没有历史版本，是字段摘要代理，不是LLM摘要 |
| lexical_top_one | 按精确字段和截止时间取最新一条；是词面代理，不是完整RAG |

每个臂保留完整120项分母。初始化/查询异常记ERROR且计错，即使参考值为null也不能算正确拒答。报告给出同一任务上的both_correct、memory_only、other_only、both_wrong，不拼接不同场景的比例。失败、逐项结果、源码清单和冻结输入均落盘；运行时源码变化会使实验失败。

2026-10-18复核：memory与event_scan均120/120；去更新115/120、去来源门110/120、去遗忘110/120、字段摘要95/120、词面首条90/120。关闭机制出现差异说明这些机制在所测任务中有作用，**不能证明完整系统优于事件扫描、独立泛化或用户效率**。见[本轮报告](../../docs/oracle/55-scoring-readiness-20261018.md)。

## 下一阶段自然语言对照的固定协议

这部分尚未执行，不包含任何虚构结果。外部出题者使用公开或合成的多会话项目材料，持有答案；开发者在冻结后不能根据保留集调参。先固定数据哈希、模型标识、reader提示、温度、输出限制、检索预算与来源规则，再统一生成所有臂；参考答案不进入生成阶段。

完整系统、普通检索、摘要记忆使用相同reader；摘要形成的额外调用也计费。分别关闭更新、来源门、遗忘时仅改变对应开关，不能同时扩大检索或改提示。记录实际模型返回标识、输入/输出usage、全部失败、逐次耗时；比较准确率、旧事实误用、拒答、端到端费用与延迟。测试顺序轮换，判读者看匿名臂标签；分歧保留并复核。

样本量与预算在实际运行前按独立先导集成本和预期效应确定，不预先承诺500题能区分任意小差异。按配对结果报告差值和不确定性；多项消融应说明多重比较。结果若与强基线持平就保留持平结论，不通过故意设置基线必错题来制造优势。

只有真实执行并完成独立判读后才能填写自然语言结果。新数据不会抹去Oracle开发暴露史，正式分数仍由项目组确定。
