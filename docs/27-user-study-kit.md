# 目标用户任务观察包（待执行）

本材料供本人招募后执行；尚未招募或访谈任何参与者。所有结果表为空，不代表已有需求验证。

**2026-10-18增加持续使用观察：** 首次任务之后隔24—72小时再恢复同一公开/合成项目，至少经历“记录决定→后续更正→保存交接→跨会话继续”四次操作。固定开始计时点为看到任务说明，结束点为给出正确状态及来源；记录同义表达查找、歧义澄清、重复待办、错误写入及撤回次数。每次修正与主持人协助都计入时间。沿用下列交叉顺序和强基线，不把熟悉过同一答案后的速度提升归功于产品。没有参与者结果时保持待执行。

## 招募与先问经历

3–5 位过去两周独立持续做公开 AI/软件实验、每周多次使用 AI 协作、发生过切换会话或暂停后恢复的学生/初级研发工程师。不要用泛泛的“你喜欢 AI 吗”筛选。

先问：最近一次重新继续实验是什么时候？你打开了哪些文件/聊天，花多久确认当前决定？能否复述一次把计划当成结果、误用旧约束或重复失败方案的经历？现在用什么方法解决？若无法给出具体重复事件，记录为需求弱证据。不要展示产品后再诱导认可。

说明：参与自愿，可随时停止；仅使用提供的公开合成项目材料，不收集私人聊天、公司资料、患者资料。记录使用匿名编号，录音需参与者单独同意。

## 材料与交叉顺序

使用 `eval/project_stories.py` 生成的两个等难度故事组，每组包含不同机制，不能让第二轮重复同一答案。A 为文档＋结构化事件表（包含全部相同材料，可搜索）；B 为工作台。P01/P03/P05 顺序 A→B；P02/P04 顺序 B→A。材料组也交叉交换。记录每次协助，主持人不在任务中提示答案。

两边均使用明确记录，避免把系统的人工结构化成本藏起来。若另测自动抽取，单独设计条件并计入校正时间，不与本实验混算。需要模型时使用同一模型、基础提示和预算，完整记下调用数及费用。

## 六项任务

1. 形成“继续工作简报”：当前采用方案、最新约束、下一项尚未确认工作，并打开来源。
2. 分数更高的备选是否已被采用？给出依据。
3. 查询更新前某一日的预算/配置。
4. 面对两条没有明确替换关系的冲突约束，说明可以和不可以做什么。
5. 问一个没有记录的实验结果，检查是否诚实保持未知。
6. 纠正一条信息并删除另一条，重新查询和重启，确认变化；计入维护时间。

主持人根据独立答案表核对，得到完整正确答案才停止“正确恢复时间”。超时 5 分钟记失败和截尾值，不能删除难题。修复用户误操作的时间计入成本。自动查询耗时不代替人的阅读和核查时间。

## 记录表模板

```csv
participant,condition,material_group,order,task,start,end,elapsed_seconds,correct,stale_state_error,source_verified,corrections,maintenance_seconds,interventions,notes
```

每位参与者保留原始记录；汇总按人先计算 A/B 中位恢复时间，再报告个体差异与总体中位比值。小样本只支持初步可用性结论，不报统计显著或市场规模。访谈语句必须区分原话、研究者解释与产品建议。

## 预先确定的去留标准

正确恢复的中位时间相对最强简单基线至少减少 25%；过期信息错误和维护负担不增加；至少 3 位目标用户能举出近两周重复困难并愿意复试。未满足则收缩为“可审计记忆模块＋摘要助手”，不包装成企业平台。

本轮构造结果显示事件扫描与系统同为 120/120，因此时间与维护成本尤其关键。实测前，不填写“效率提高”“已验证痛点”等宣传结论。
