## 一个入口重跑

在实际仓库根目录按 README 安装开发依赖后执行：

```text
python tools/check_quality.py --output artifacts/my-quality-run
```

输出目录必须不存在。每个命令的输出、完整 JUnit、逐文件覆盖率、覆盖率分母、跳过原因和源码哈希都会保存；失败也保留结果。执行前后的源码清单必须一致，否则本次门禁失败。哈希仅将 CRLF 归一化为 LF，便于跨操作系统比较。

门禁清除继承的 `DIVE_*` 配置并设置本地证据模式，避免开发者的在线配置进入默认工程验证。PG 真正服务测试仍在独立 CI 作业设置连接信息运行；不把默认离线检查当作 PG 通过。依赖锁新增 coverage 7.13.1；运行时不增加依赖。

自动检查范围明确区分：

- 全部 `src` 扫描 E9/F63/F7/F82 等语法、未定义名称与严重逻辑诊断。本轮移除的 `_sha256_text` 为无调用点的遗留私有函数，没有更改 Oracle 策略。
- 交付代码、启动器、相关测试与维护工具执行项目配置的全部 Ruff 规则和格式检查。类型检查覆盖交付的 12 个模块，含未注解函数体；导入仍使用 skip，**不是全包严格类型检查**。
- 全包收集行与分支覆盖率；两组关键路径分别执行 90%/80% 门槛。门禁拒绝缺文件、未采集分支数据、空分母，以及四舍五入后才达到的百分比。
- 历史源码仍有 **113 项完整 Ruff 规则诊断**，主要是导入/风格与宽泛异常处理。完整诊断随证据保留，本轮没有通过批量禁用规则或删除旧测试隐藏它们。
