## 为什么改变引用协议

真实失败发生在搜证计划阶段。第一轮输出把上下文的证据编号重新排成笔记序号；既定的一次修正纠正了多数编号，但又将一段原文的开头改为大写。两次都未通过严格的原句与当前片段校验。原文校验正确地拒绝了不一致引用，这不是已经证明的内容答题错误。

自由生成答案是模型的工作；逐字复制原句同时维持来源编号则增加了可避免的协议失败点。新的`deliberative-refs`策略让模型返回当前上下文的`source_indices`，宿主程序从对应可见片段提取完整原文、记忆编号和来源。模型没有提供可被程序模糊匹配或修补的引文。

## 实现与解耦

- [阶段协议接口](../../src/dive_memory/reading/deliberation.py)封装提示、解析器和来源索引提取。旧文字引用协议作为默认实例保持，旧策略名称及提示版本不变。
- [来源编号协议](../../src/dive_memory/reading/references.py)只接受当前有效整数编号，拒绝重复、越界、缺来源、空片段、额外字段或重复JSON键。计划最多16个来源，搜索和读取继续使用原范围约束；答案可引用全部实际可见前提。
- [三阶段编排](../../src/dive_memory/reading/deliberative.py)通过协议注入复用搜证、合成和复核，仍是3个必需阶段、共享最多1次格式修复、最多4次模型调用。来源与引用仍通过原证据工作区绑定文档和位置。
- [应用工厂](../../src/dive_memory/application/readers.py)、设置、Oracle入口和开发挑战工具显式支持`deliberative-refs`；默认策略没有自动切换。

派生答案仍由模型判断。真实来源编号不证明该来源支持答案，模型选错编号仍可能产生有合法出处但语义错误的回答。完整片段引用也可能比短引文占用更多保留空间，挤压新反证或增加提示费用。新协议没有解决记忆漏写、范围推理或judge分歧，必须真实测量改善与退步。
