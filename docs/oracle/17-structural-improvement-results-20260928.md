# 结构性改进：事件原句、语义检索与有界补查

日期：2026-09-28。前序结果见 [完整 500 题测试](15-flash-full-test-20260927.md) 与 [v4 配对实验](16-v4-improvement-results-20260927.md)。

本轮已完成实现、六组离线消融、80 题配对筛选与一次完整 500 题复测。**事件原句＋本地语义检索将非官方自评从 289/500 提高到 311/500（57.8% → 62.2%，+4.4 个百分点）**。采用此组合作为下一轮实验基线，不开启未显示额外收益的补查，也不扩大预算。付费请求已停止，余额观察差额为 **¥2.81**。这不是正式比赛成绩，也不代表剩余错误已解决。

## 1. 这轮要解决什么

此前完整测试为 289/500，存在两个不能只靠改提示词解决的问题：有些个人经历没有形成记忆；另一些已经留下的证据被词面排名挤出前十。与此同时，“标注来源已装包”不等于答案所需句子齐全，更不等于 reader 能正确推理。

这轮把改动落到写入、检索两层，保留 v3 reader 不变，再用独立的来源诊断观察阅读端。没有引入图数据库，没有把全部原始历史变成可搜索记忆，也没有把参考答案用于运行时决策。

## 2. 实现细节与取舍

### 2.1 个人经历不必先变成稳定事实，才有资格被记住

新增 `src/dive_memory/episodic_retention.py`。普通抽取结束后，可选策略检查尚未保留的用户原句：必须有第一人称、经历或状态动词，并含具体时间、数量或命名对象；排除疑问、计划、假设等表达，整回合命中现有敏感信息检测则不增加事件记忆。每回合最多增加 4 条，每句最多 1,000 字符，超过 8,000 字符的回合不经此旁路保留。

保留的是原句及字符区间 `source_span`，类型为 `episode`，证据状态为 `OBSERVATION`，而不是已核实的事实。其谓词为 `episodic_statement`，不会把不同经历误当成同一个标量属性的相互覆盖，也不自动写进当前用户档案。它使用原来的命名空间、索引、时间过滤、生命周期和删除机制。

这实际上增加了一条有界、与问题无关的写入规则，不是声称原有写入门完全不变。实现包括金额小数与 `Dr. Smith` 一类称谓的分句保护。它仍是规则筛选，不理解所有否定、引语和指代，中文覆盖也远少于英文；敏感检测同样不构成完整隐私保证。适合作为可审计的增量方案，不宜宣传成通用事实抽取器。

### 2.2 把真正的语义检索与写入门分开测

原来的语义写入门使用本地模型，不代表检索端也使用了语义向量。新实验显式将本地 BGE-M3 接入检索，并在主检索通道关闭 BM25，与旧词面/结构化方案比较。实体、谓词、时间等结构化通道仍在；助手文档补入仍有独立词面通道。因此这里的“semantic”不是全系统只剩向量搜索。

模型固定为 `BAAI/bge-m3`，revision 为 `5617a9f61b028005a4858fdac845db406aefb181`。复用本地缓存，不下载模型，不调用付费 embedding。编码器输入长度为 512，不能据此宣称发挥了 BGE-M3 的全部长文本能力。文本向量缓存上限 4,096 条，不存问题标签或答案。

### 2.3 缺少复合问题的一侧时，只补查一次

新增 `src/dive_memory/evidence_search.py`。对包含数量、时长、差值等词语的复合问题，最多拆成两个探针；当已有候选没有同时满足内容词和数字匹配时，才搜索对应一侧。每个探针最多增加两条新记忆，尽量保护原排名前六条，最终仍受 top-k 和总阅读预算约束。新增、挤出以及查到的记忆 ID 均进入 trace。

这个模块不调用 LLM，不查原始历史，不看参考答案。但“词汇匹配＋数字”只是缺失前提的粗略代理，不能证明证据充分，亦不是时间/金额计算器。它可能发现不了语义上缺失的前提，也可能把别的数字误当作已覆盖。因此先作为实验开关，不直接默认开启。

## 3. 实验边界

数据为 Oracle 500 的公开开发数据。这轮固定抽取 50 道可答题，加上全部 30 道不可答题；排除此前指定小样本中的可答题及若干已讨论案例，不按旧版答对与否抽样。由于完整公开集曾被测试与分析，这不是未见过的独立留出集。

固定随机种子、数据哈希、源码与运行环境快照、reader v3、DeepSeek Flash、top-10、文档补入策略。前五组阅读预算均为 1,500 近似 token；只有 `roomy` 为 3,000。这个预算衡量证据块，不包括全部 API 指令，也不是服务商账单 token。1,500/top-10 是项目实验配置，不是已确认的主办方硬性要求。

旧版 80 题阅读包已逐一重放，80/80 与保存的完整测试一致。这批旧版为 46/80，其中可答题 23/50、不可答题 23/30；不能与上一轮另一批 80 题的总分直接比较。

实验目录：`eval/reports/oracle-structural-20260928-v2/`。不带 `-v2` 的同日目录是分句修复前主动中止的离线尝试，没有 API 调用，不纳入本轮结论。

本批可答题共有 95 个标注来源回合。数字是来源回合覆盖，不是句子完整率，也不是正确率。

## 5. 来源诊断不属于可提交成绩

另取 18 道完整标注来源回合能装入 1,500 token 的可答题，跳过写入和检索，将这些来源交给同一 v3 reader；reader 不接收参考答案。此条件使用了标注来源，只是评估工具，不生成提交文件。

旧版答对 9/18，来源诊断答对 13/18：5 道由错变对、1 道由对变错。这说明证据选择和原文完整性值得改进，也说明即便给予标注来源，阅读与推导问题仍在。这个小样本有长度筛选偏差，来源标注也不等于人工确认所有前提完备；13/18 既不是系统正确率，也不是理论上限。

### 6.2 完整 500 题

已全部完成，`completion.json` 为 `COMPLETED`，全部 500 个判分结果均与对应答案摘要及数据哈希校验通过。

| 题型 | 题数 | 旧版答对 | 新版答对 | 净变化 |
|---|---:|---:|---:|---:|
| 跨会话 | 133 | 61 | 73 | +12 |
| 时间推理 | 133 | 62 | 66 | +4 |
| 助手历史内容 | 56 | 39 | 42 | +3 |
| 信息更新 | 78 | 53 | 56 | +3 |
| 用户事实 | 70 | 58 | 58 | 0 |
| 偏好 | 30 | 16 | 16 | 0 |
| **合计** | **500** | **289** | **311** | **+22** |

这里的六个题型包含各自的不可答变体。若另外按可答性拆分，可答题为 **266/470 → 288/470**；不可答题为 **23/30 → 23/30**。新方案规范拒答 23 道不可答题，另有 6 道错误作答、1 道无效输出。

配对结果是 49 道由错变对、27 道由对变错，262 道均正确、162 道均错误。没有任何大类总分下降，但仍有 27 个具体退步案例，因此不能说新版逐题优于旧版。小样本中的偏好退步没有演变为全类总分下降，不过全量偏好误拒从 8 增至 12，建议型问题仍是风险点。

用于筛选的 80 题从 46 提高到 52；其余 **420 题从 243 提高到 259，净增 16 题**。这说明收益不只来自筛选样本，但 420 题仍来自此前用过的公开开发集，不是独立盲测。49/27 的配对变化对应双侧精确 McNemar p≈0.0154；这是探索性统计，不纠正多轮开发与选版偏差，不能替代正式评测。

可答题误拒由 **115 降至 100**；全部错误作答由 **90 降至 80**；无效输出由 **6 增至 9**。9 个无效输出包括：6 个拒答中混入答案或引用、2 个引用不存在于候选集的记忆、1 个引文不是原文连续子串。它们全部计错；提交文件中的规范兜底文本不算成功拒答。

形成来源回合从 **781/886 → 836/886**，检出从 **636/886 → 720/886**，装包从 **635/886 → 720/886**。说明这轮确实缓解了写入遗漏和检索遗漏，而不是靠更大的模型或阅读预算提高分数。剩余 189 道错题按首个可观测缺口分为：形成不足 36、检索不足 53、装包不足 0、来源回合均已装包但仍错 85、无效输出 9、不可答错误作答 6。该归类优先识别无效输出，不等于因果证明；尤其 85 道“来源已装包”仍可能存在关键句缺失，不能全部算成纯推理错误。

预算审计覆盖全部 500 题，证据块近似 token 中位数 851.5、最大 1,480，0 题超过配置的 1,500。筛选与全量重叠的 80 题形成、检索及阅读包 80/80 一致；运行结束后源码与环境快照仍一致。

完整提交文件为 `eval/reports/oracle-structural-20260928-v2/full-episodes-semantic/submission.jsonl`：500 行、500 个唯一 ID，0 缺失、0 重复、0 空答案，格式校验 `VALID`。**仅在本地生成，没有上传到比赛系统。**

### 6.3 实际费用与采用决定

本轮新增 API 请求 **832 次**，缓存命中 **726 次**（其中从此前实验缓存复用 454 次）；新增请求累计输入 **1,378,431 token**、输出 **85,776 token**，没有用量未知的请求。余额观察为 **¥17.57 → ¥14.76，差额 ¥2.81**。差额可能受延迟结算或账户其他使用影响，不是单价核算账单。

此轮不用再付费跑补查或 3,000 token 方案。将 `episodes-semantic` 作为后续 Oracle 开发的推荐实验配置，保留旧方案以便回退；通用 CLI 默认仍不静默改变。真实答题已经支持采用这次写入与检索组合，但还不支持宣称达到高分终点，更不能把 62.2% 换算为主办方正式得分。

### 6.4 已定位但本轮尚未解决的结构性问题

`001be529` 问庇护申请等了多久。标注原回合中有明确的 “Over a year of uncertainty”，但正常新方案仍拒答；直接给完整标注来源后答对。新增规则要求单句包含第一人称、事件动词及细节，这种跨句表达可能不满足条件。它说明“保留事件原句”只缓解了抽取损失，还需要处理邻接句、指代和叙事片段的关联，不能把覆盖到某个来源回合当成保住关键句。

两道不可答退步题则表明“检到语义相近的记忆”不等于“所问对象和必要数值被支持”。下一阶段需要实体角色与推导前提校验。单纯提高相似度、扩大预算或上图数据库，都不能自动解决父亲/姐姐、公交费用/出租车费用的错配。

## 7. 工程检查与剩余边界

本轮最终回归测试：538 passed、9 skipped。新增测试覆盖事件原句的来源区间、金额与称谓分句、敏感信息与假设过滤、默认行为不变、隔离和删除传播，以及补查调用上限、去重、保护已有候选和选版约束。补充验证了关闭记忆后的同步写入和后台投影均被阻止，重新开启也不会补写被禁止的事件。跳过项不能算已验证通过。

目前未实现强类型时间/金额计算器，也未获得主办方正式 judge 版本。DeepSeek Flash 同时充当 reader 和 judge，存在同源偏差；所有真实答题分数均是非官方自评。后续应从错误案例判断是否需要关系遍历、重排或计算器，而不是因为模块存在就全部开启。

## 8. 怎样复核，而不是重复花钱

首先阅读实验目录下的 `frozen-plan.json`（固定条件）、`offline-summary.json`（覆盖消融）、`baseline-replay-audit.json`（旧版阅读包一致性）、各 `*-evaluation.json`（答对率和逐题结果）。`diagnostic/` 必须与正常方案分开解释；它不是提交结果。

本轮驱动入口是 `ops/oracle_structural_experiment.py`，必须使用已配置本地 BGE 的 `.venv-gpu` 环境。源码和环境未变化时，加 `--offline-only --output eval/reports/oracle-structural-20260928-v2` 可以重读/续跑离线部分，不会请求 API。源码快照不匹配会停止，不能强行混用修改前后的结果。

去掉 `--offline-only` 才进入付费流程，密钥通过隐藏输入读取，不写入源码或报告。缓存以请求内容匹配，能复用的 reader/judge 不再调用。余额每 20 次新请求观察一次，观察差额达到 ¥3 停止；另有新请求 1,600 次、累计 350 万 token 的上限。余额可能延迟或包含账户其他使用，这不是保证分毫不超的实时账单硬限。

新功能均为显式开关：`--episodic-retention`、`--semantic-retrieval-only`（要求真实本地 embedder）、`--evidence-recovery`。本轮胜出的筛选配置开启前两项，不开启第三项，保留 reader `evidence_first`、`balanced` 评分、`query_excerpt` 文档选段、`controlled_supplement` 文档补入、top-10 和 1,500 证据预算。普通 CLI 默认没有被偷偷替换，旧实验仍可复现。
