# 工作区与工程证据维护

源码、使用说明和精选验收结果分别放在`src/`、`docs/`和`artifacts/`。完整实验、失败日志、缓存归档及本机构建结果留在被Git忽略的`eval/reports/`。`audit_tools/`是有测试和历史实验引用的审计入口，不是临时缓存。

## 预览与清理

在仓库根目录先运行预览：

```text
python tools/clean_workspace.py
```

工具只考虑根目录的pytest、Ruff、Mypy、npm缓存、旧`build/`副本，以及空的`deploy/`目录。旧`.pytest-*`目录中的测试数据库和快照会先保存为ZIP并逐文件校验，再移除原临时目录。`dist/`中的旧安装包、模型、Python环境、用户项目数据库、原始评测、文档草稿和其他目录都不在清理范围。

确认清单后执行，并指定一个新的记录目录：

```text
python tools/clean_workspace.py --apply --output eval/reports/my-cleanup
```

默认预览不删除文件。执行时检查Git仓库根路径、跟踪文件、Windows路径大小写、符号链接及reparse point；无法完整读取的候选会保留并在`blocked`列出。每个目标删除前重新核对文件清单和哈希，观察到新写入时保留该目标。请在测试和构建进程停止后清理，工具不提供跨进程文件锁。

记录目录包含`cleanup.json`及需要时的`pytest-temporaries.zip`。原始归档可能包含测试数据库和旧内容，不应直接推送。公开只保留清理摘要、文件数量、体积和归档哈希。

## 避免重新产生杂物

- 完整工程检查使用新的`eval/reports/<本轮>/quality-v1`目录，不覆盖旧失败；检查自身保存源码哈希和跳过原因。
- 浏览器合成项目放在本次专用的系统临时目录，结束后清理；截图和验收摘要才进入报告目录。
- Docker构建忽略缓存、构建副本、本地状态和环境配置；实际服务运行与安装仍由远程检查验证。
- 源码绑定覆盖Python、前端、浏览器脚本、打包数据、依赖锁、CI、迁移和部署配置。文本统一LF，二进制按原字节计算；检查期间这些文件改变会使门禁失败。

本轮结果见[R64记录](oracle/59-engineering-hygiene-20261023.md)。工程测试与覆盖率分别报告，不作为Benchmark准确率或评委19/20的替代。
